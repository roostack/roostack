Design system

Every colour, size and component MyLab's pages use, in light and dark. Pages should only use what's here; if something new is needed, add it to the design system first (docs/DESIGN.md).

Two kinds of component: template components have shared markup and are called as functions, e.g. {{notice "warn" "…"}} (the markup shows the call and the HTML it renders); HTML and CSS classes are written as plain HTML using the classes shown.

This file is generated from the same templates as the /design page in MyLab (go test ./internal/web -run TestGalleryFile -update-gallery). Don't edit it by hand.

Confirm Template component

confirm ACTION QUESTION TEXT KIND: a button that asks the browser to confirm first. Use it for anything hard to undo. KIND is the button's class (danger, secondary, quiet, or ""). The question can contain any text (it's passed as a data attribute, never into script).

Activity

Operations on the host (OS updates, backups, applying changes, restores): a status line everyone can follow, with the full log under Details. While running, the status line and log refresh themselves.

Running Template component

The handler looks up the latest run of a kind, e.g. data["UpdatesActivity"] = s.activityFor(r, activity.OSUpdates), and the page passes it to activity (which shows nothing if there's none). Steps come from the operation's own log (activity.Log.Step).
