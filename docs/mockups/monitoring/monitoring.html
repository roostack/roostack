Checking

How it checks
Services
Every minute, nuc (the lab's controller) asks each service's address over the lab network, at the server it runs on, using its name, so it checks that server's Caddy and certificate whatever DNS and your router do. Up means it connected, the certificate is valid for the name, and an answer came within 10 seconds with a status below 500 (a login page or "sign in first" counts as up).
Problems
Three failed checks in a row (so one slow answer emails nobody); fixed at the first good one. A service stopped on purpose, installing or updating, or a server restarting in its window, is paused.
Certificates
A warning when less than a fifth of a certificate's life is left: Caddy renews at a third, so renewing is failing.
History
Every result for two days, then each hour's summary, kept as long as History keeps things (90 days). In the controller's database, /var/lib/roostack/roostack.db.
Status page
A plain file Roostack writes every minute, /var/lib/roostack/status/index.html, served by Caddy at status.smiths.roost.ac. Nothing on it runs code.
