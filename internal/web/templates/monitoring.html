Checking

{{if .On}}Turning monitoring off stops the checks and their emails.{{else}}Monitoring is off: nothing is checked, and nobody is emailed.{{end}} Services' own health checks, and the rest of "needs attention", carry on.

{{end}}
How it checks
Services
Every minute, {{or .CheckedFrom "this server"}} (the lab's controller) asks each service's address through its own Caddy, which serves every address in the lab, using the address's name, so DNS and your router don't come into it. Up means it connected, the certificate is valid for the name, and an answer came within 10 seconds with a status below 500 (a login page or "sign in first" counts as up), unless the service's package says otherwise.
Servers
Each of the lab's other servers must accept a connection on the lab network (port 8471).
Problems
Three failed checks in a row (so one slow answer emails nobody), shown under "needs attention" and emailed once they've lasted a few minutes; fixed at the first good one. A service stopped on purpose, starting, being set up, updated or restored, or whose server isn't answering, is paused.
Certificates
A warning when less than a fifth of a certificate's life is left: Caddy renews at a third, so renewing is failing.
History
Every result for two days, then each hour's summary, kept as long as {{if .IsOwner}}History{{else}}History{{end}} keeps things, in the controller's database.
{{if .StatusHost}}
Status page
A plain file Roostack writes every minute, served by Caddy at {{.StatusHost}}. Nothing on it runs code.
{{end}}
