Storage for others

Give family or friends space on this server for their Roostack's backups, and they can do the same for you: each of you then has a copy somewhere else. Their backups are encrypted before they leave their lab, so you can't read them, and each lab gets its own space with a size limit.

Letting them in: your provider's firewall

Roostack already allows other labs through {{.HostServer.Name}}'s own firewall. If your cloud provider puts a firewall in front of it (such as Linode's Cloud Firewall or AWS security groups), allow UDP port 51821 from anywhere in its control panel. No provider firewall? There's nothing to do.

How to tell it worked: once they've used the invite, "Connected" above shows when their lab last reached this one.

{{else}}
Letting them in: port forwarding

Other labs connect to {{.HostServer.Name}} through the router in front of it, which only lets them in if you ask it to. Roostack already allows it through {{.HostServer.Name}}'s own firewall; the router is the step it can't do for you. (A server in the cloud usually has no router to set up: only its provider's firewall, if any.)

  1. Open your router's settings page (often http://192.168.1.1 or http://192.168.0.1; the address and password are usually on a sticker on the router).
  2. Find Port forwarding. Some routers call it Virtual server, NAT, Port mapping or put it under Advanced or Firewall.
  3. Add a rule: protocol UDP (not TCP), port 51821, to {{.HostServer.Name}}{{with .LANAddr}} at {{.}}{{end}}, port 51821.
  4. Use your home's public address in the invite, e.g. 203.0.113.7:51821. Search "what is my IP" from a device at home to find it.

How to tell it worked: once they've used the invite, "Connected" above shows when their lab last reached this one. If it stays "Not yet", the port isn't forwarded (or the address is wrong). Some internet connections (called CGNAT) can't forward ports at all; then the other lab can host instead, and you store at theirs.
