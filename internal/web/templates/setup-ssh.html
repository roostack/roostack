Set up an SSH key

{{icon "close"}}Close

A key is a pair of files on your computer that lets you log in without typing a password. Unlike a password, it can't be guessed, so once it works Roostack can turn passwords off.

  1. Make a key on your computer. Skip this if you already have one.
    {{segmented "os" "Your computer" "windows" (choice "windows" "Windows") (choice "mac" "macOS") (choice "linux" "Linux") "size=small"}}

    Open PowerShell (from the Start menu) and run:

    {{template "copy-box" "ssh-keygen -t ed25519"}}

    Press Enter to keep the file where it suggests, and choose a passphrase, which protects the key if someone gets your computer. Then show the public key:

    {{template "copy-box" "type $env:USERPROFILE\\.ssh\\id_ed25519.pub"}}

    Open Terminal (in Applications, Utilities) and run:

    {{template "copy-box" "ssh-keygen -t ed25519"}}

    Press Enter to keep the file where it suggests, and choose a passphrase, which protects the key if someone gets your Mac. Then copy the public key:

    {{template "copy-box" "pbcopy < ~/.ssh/id_ed25519.pub"}}

    Open a terminal and run:

    {{template "copy-box" "ssh-keygen -t ed25519"}}

    Press Enter to keep the file where it suggests, and choose a passphrase, which protects the key if someone gets your computer. Then show the public key:

    {{template "copy-box" "cat ~/.ssh/id_ed25519.pub"}}
  2. Paste your public key, and choose the account. {{/* Never sent: it's a form for its fields' look, and Enter does nothing. */}}

  3. Add it on the server.

    In a terminal on the server, as root: the one you installed Roostack from, or your provider's web console. If you're logged in as another account, run sudo -i first. The commands will have your key in them once you've pasted it.

    {{if not .KeyForm.Existing}}useradd --create-home --groups sudo --shell /bin/bash {{.KeyForm.NewUser}}
passwd {{.KeyForm.NewUser}}
{{end}}{{with or .KeyForm.Existing .KeyForm.NewUser}}mkdir -p -m 700 ~{{.}}/.ssh
echo 'your public key' >> ~{{.}}/.ssh/authorized_keys
chown -R {{.}}: ~{{.}}/.ssh
chmod 600 ~{{.}}/.ssh/authorized_keys{{end}}

    passwd will ask for the new account's password twice. You'll need it for sudo, and for logging in at the server's own screen or your provider's web console, but SSH won't take it once it's keys only.

    {{if .SSHD.Passwords}}

    Or, if you know the account's password, run this on your computer instead:

    {{end}}
  4. Log in with it once. On your computer, run: 
    ssh {{or .KeyForm.Existing .KeyForm.NewUser}}@{{.SSHHost}}

    The first time, SSH will ask whether you trust the server: type yes. It will then ask for your key's passphrase, if it has one, but not for the account's password.

    {{template "ssh-key-status" .}}
Why Roostack doesn't add the key itself

roostack-agent, the part of Roostack that runs as root, has no way to add a key or make an account, so nothing running as Roostack (a service that's been taken over, say) can give itself a way in as root. The commands make ~/.ssh (700) and add your key to authorized_keys in it (600), both owned by the account, as SSH requires. Roostack sees the login in SSH's log, written by sshd itself (journalctl _UID=0 _EXE=/usr/lib/openssh/sshd-session).
