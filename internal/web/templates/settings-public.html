For technical users

The cloud server's Caddy routes each connection on the name in its TLS handshake, using Caddy's layer-4 plugin, and passes it over Roostack's WireGuard network to this server's port 443 with a PROXY protocol header saying who the visitor is. TLS ends here, with this server's certificate. This server believes that header only from the cloud server's WireGuard address, and treats that address as outside, so private paths stay private even if a header went missing. HTTP/3 (UDP) doesn't pass through: browsers use HTTP/2 instead.

For technical users

The relay's edges look up each visitor's address in DB-IP's free country database (IP geolocation by DB-IP, updated monthly) and close connections from countries this lab doesn't let in, before passing anything on. An address the database can't place counts as from no country, so a list of countries let in turns it away. Addresses this lab's CrowdSec bans are sent to Roostack Cloud every 5 minutes and turned away at the edges too, for this lab only.

Sharing attack reports

While anything is public, CrowdSec can share the attacks it sees with its community: only attackers' addresses and what they tried, never anything about you or your people. In return, addresses others have seen attacking will be blocked before they try.
